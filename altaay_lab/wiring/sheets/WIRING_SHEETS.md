## How to regenerate

```
python3 altaay_lab/wiring/sheets/make_sheets.py            # writes the 5 SVG + PNG and this file
python3 altaay_lab/wiring/sheets/make_sheets.py --strict   # also fails on any layout warning
```

Needs Python 3 with matplotlib, PyYAML and Pillow, and the Carlito font (Debian/Ubuntu package fonts-crosextra-carlito). `ODM_NETLIST=path` points the generator at another netlist. Layout lives in `make_sheets.py` (one function per sheet); drawing rules and checks live in `sheetlib.py`: the run stops on an unknown pin pair, a diagonal segment, a wire leaving a terminal the wrong way, a slot used twice, a stub whose wire is not drawn in full elsewhere, or a dash in any drawing text. Layout warnings (labels on other wires, wires through blocks, overlaps) are printed; `--strict` turns them into errors. This run printed 90 layout warning(s).

## Conventions on the sheets

- Seen from behind: robot left is on the left (netlist meta).
- Wire colour = insulation colour from the netlist, with the IEC 60757 code in the label (RD, BK, YE, WH, GN, BU, OG, BN). Grey with white dashes = colour not set by the netlist (kit servo cables, fuse holder leads). Thin grey = bare resistor lead (0 mm wires in the netlist).
- Line weight follows the gauge. Label = cable id (as in CABLE_MAP.md), branch when the netlist has one, gauge, cut length ("as shipped" when the netlist has none), colour code.
- Splices are black dots; a hop is a crossing with no contact; a cross marks a pin that is not connected (nc in the netlist).
- Resistor leads that are soldered straight to a pin carry one tag per resistor instead of a label on each 0 mm lead.
- The servo housings are drawn D V G with V in the middle. The neck row on sheet 2 is drawn G V D only to keep the Y splices from crossing. The netlist numbers the servo pins as the Feetech sheet does (1 GND, 2 Vcc, 3 signal); the Waveshare adapter counts from the other end (1 D, 2 V, 3 G).

## Netlist questions

Open:

1. Component refs D2, D3, D4, D5 are also cable ids (D2, D3, D4, D5 in `cables`): rename them so a label is never ambiguous.
2. Terminal order on the board is marked [I] (not checked) for BNO055, MAX98357A, D30V30F5 and the charger pads, and the panel switch lugs are [I]. The sheets draw these blocks in the order that keeps the wires straight and say so on the sheet; check the order on the parts.

Answered in the netlist pass of 2026-11-02: the LED refs are LED1 to LED3 and the panel switch is SW2; the servo BUS pins carry the Feetech pin numbers (STS3215 sheet item 6-7), and the build sheets say to copy a kit cable housing and check with a meter; SW1 and U1 pins have printable labels (SW, GND, IN+, IN-, 1+, 1-, 2+, 2-); the BEC output lead and kit cable gauges are not published, so they stay as shipped (no AWG in the netlist).
