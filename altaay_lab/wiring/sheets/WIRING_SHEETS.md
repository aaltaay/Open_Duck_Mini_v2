## How to regenerate

```
python3 altaay_lab/wiring/sheets/make_sheets.py            # writes the 5 SVG + PNG and this file
python3 altaay_lab/wiring/sheets/make_sheets.py --strict   # also fails on any layout warning
```

Needs Python 3 with matplotlib, PyYAML and Pillow, and the Carlito font (Debian/Ubuntu package fonts-crosextra-carlito). `ODM_NETLIST=path` points the generator at another netlist. Layout lives in `make_sheets.py` (one function per sheet); drawing rules and checks live in `sheetlib.py`: the run stops on an unknown pin pair, a diagonal segment, a wire leaving a terminal the wrong way, a slot used twice, a stub whose wire is not drawn in full elsewhere, or a dash in any drawing text. Layout warnings (labels on other wires, wires through blocks, overlaps) are printed; `--strict` turns them into errors. This run printed 0 layout warning(s).

## Conventions on the sheets

- Seen from behind: robot left is on the left (netlist meta).
- Wire colour = insulation colour from the netlist, with the IEC 60757 code in the label (RD, BK, YE, WH, GN, BU, OG, BN). Grey with white dashes = colour not set by the netlist (kit servo cables, fuse holder leads). Thin grey = bare resistor lead (0 mm wires in the netlist).
- Line weight follows the gauge. Label = cable id (as in CABLE_MAP.md), branch when the netlist has one, gauge, cut length ("as shipped" when the netlist has none), colour code.
- Splices are black dots; a hop is a crossing with no contact; a cross marks a pin that is not connected (nc in the netlist).
- Resistor leads that are soldered straight to a pin carry one tag per resistor instead of a label on each 0 mm lead.
- The servo housings are drawn D V G with V in the middle. The neck row on sheet 2 is drawn G V D only to keep the Y splices from crossing; the cavity order itself is not in the netlist (see the questions below).

## Netlist questions found while drawing

1. Component refs D1, D2, D3, S1 are also cable ids (D1, D2, D3, S1 in `cables`), for example LED D1 and USB cable D1. Proposed: rename the LED refs to LED1 to LED3 and the panel switch to SW2 so a label is never ambiguous.
2. The STS3215 BUS 1 and BUS 2 groups name the pins D, V, G but give no cavity numbers, and the made leads SP1 to SP3, SD1 and SD2 need them at the servo end. TEST_PLAN.md says GND, VCC, DATA per the Feetech sheet. Proposed: add pin numbers to the servo groups (and confirm against a kit cable).
3. Terminal order on the board is marked [I] (not checked) for BNO055, MAX98357A, D30V30F5 and the charger pads, and the panel switch lugs are [I]. The sheets draw these blocks in the order that keeps the wires straight and say so on the sheet; check the order on the parts.
4. SW1 pins SW and GND_SW have label "switch symbol", and U1 pins have lead colours as labels. The sheets show SW, GND, IN+, IN-, 1+, 1-, 2+, 2-. Proposed: give these pins printable names in the netlist.
5. P11 lead wires have gauge "BEC lead" and no cut length, and kit cables have no colour; the sheets show "as shipped" and grey. If the BEC output lead gauge is published, adding it would let the rule check test ampacity there.
